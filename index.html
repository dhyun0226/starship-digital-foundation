01 · Private by default

인터넷 진입점은 WAF·ALB로 제한하고 EC2, RDS, S3는 직접 공개하지 않습니다.

02 · 공고 기반 기술

EC2·RDS·S3를 우선 사용합니다. 컨테이너는 EC2 위 Docker로 시작하고 복잡한 오케스트레이션은 보류합니다.

03 · Build once

검증한 동일 이미지를 DEV→STAGE→PROD로 승격하고 운영 배포에는 승인을 둡니다.

04 · Source of truth

직원·조직 데이터는 기존 HR 또는 그룹웨어를 원천으로 사용하고 평가차수별 스냅샷을 보존합니다.

05 · Detect before report

CloudWatch와 CloudTrail로 장애·변경을 추적하고 개발·보안·인사·외부업체의 대응 범위를 나눕니다.

입사 후 결정

기존 AWS 계정, 접근 방식, MSP, 이중화, RTO/RPO, 예산과 개인정보 정책을 확인한 뒤 확정합니다.

01 · 제품이 먼저

디자인시스템 전체를 먼저 만들지 않습니다. 인사평가에 필요한 UI부터 구현하고 반복되는 것만 승격합니다.

02 · Token → Pattern

색상·간격 같은 Token에서 시작해 컴포넌트와 승인·검색·권한 같은 업무 패턴으로 확장합니다.

03 · 업무 UI는 단순하게

CHEESE라는 이름은 기억점을 만들지만 실제 내부 업무 화면은 명확성과 접근성을 우선합니다.

04 · 공식 홈페이지는 예외

브랜드·아티스트 표현이 핵심인 홈페이지에는 공통 Token만 공유하고 Creative Freedom을 보장합니다.

05 · 문서가 제품

컴포넌트 수보다 사용 기준, 상태, 접근성, Do/Don't를 남겨 다음 개발자가 바로 재사용하게 합니다.

성공 기준

두 번째 제품에서 UI 중복 구현과 개발 리드타임이 실제로 감소할 때 디자인시스템이 성공한 것입니다.

DECISION PRINCIPLES

Simple · Secure · Observable · Reusable

Managed over operated

한 명이 지속적으로 운영 가능한 관리형 서비스를 우선합니다.

Modular monolith first

필요성이 확인되기 전에는 MSA·Kubernetes 같은 복잡성을 추가하지 않습니다.

Evidence before scale

트래픽·장애·비용을 측정한 뒤 이중화와 확장을 결정합니다.

Document decisions

무엇보다 왜 선택했는지를 ADR과 Runbook에 남깁니다.
